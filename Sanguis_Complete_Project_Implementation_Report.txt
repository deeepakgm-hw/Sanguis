3. SYSTEM WORKFLOWS
---------------------------------------------------------------------------

WORKFLOW A: REAL-TIME DONOR GPS TELEMETRY & SECURE SYNC
1. Consent: User opts into location sharing via `LiveLocationControl`.
2. Telemetry Watch: `watchPosition` captures coordinates, heading, speed, and accuracy in `location.service.ts`.
3. Socket Transport: Sends `donor:location_update` events via Socket.IO.
4. Security Guard: Backend socket middleware extracts `userId` strictly from the decoded JWT payload (`socket.data.user.sub`). Identity spoofing is prevented.
5. In-Memory Cache: Coordinates are cached via `GEOADD` into the Redis key `sanguis:donors:locations` with a 120s TTL cutoff.
6. DB Persistence: Updates the Mongoose `Donor` model schema.

WORKFLOW B: CONVERSATIONAL AI REQUIREMENT COLLECTION
1. Text Input: User enters a prompt in the chat box on the `/find-blood` page.
2. REST Endpoint: Client fires a POST request to `/api/v1/ai/parse-requirement` carrying chat history and the accumulated parameter state.
3. Gemini AI Call: The backend requests a structured JSON response from `gemini-1.5-flash` using `AI_API_KEY`.
4. Fallback Path: If the Gemini API key is missing or the external call fails, the system runs a local rule-based regex parser and returns an offline indicator.
5. Conversation Flow: Gemini returns extracted fields (`bloodGroup`, `quantity`, `location`, `urgency`) and a list of `missingFields`. If fields are missing, the AI naturally prompts for them.
6. Confirmation: Once all fields are present, the client displays a confirmation summary. Upon user approval, the Sanguis backend database is queried.

WORKFLOW C: REGIONAL SUPPLY PROXIMITY SEARCH
1. Backend Query: Controller calls `inventoryService.getRegionalSupplyIndex` with requested blood type and coordinates.
2. Database Filter: Queries verified blood banks using MongoDB 2dsphere geospatial indexing (`$near` / `$maxDistance`).
3. Matching Check: Verifies inventory stock counts (`unitsAvailable >= requestedQuantity`).
4. Display: Nearby banks are returned to the client and rendered as markers on the Leaflet 3D perspective map.
5. Action Routing: Users click "Get Directions" to launch Google Maps with the origin and destination coordinates configured.

4. DATABASE MODEL SCHEMAS
---------------------------------------------------------------------------

1. USER MODEL (models/User.ts)
   - name: String (required)
   - email: String (unique, required)
   - role: String ("user", "donor", "hospital", "admin")
   - isEmailVerified: Boolean

2. DONOR MODEL (models/Donor.ts)
   - userId: ObjectId -> User
   - bloodType: String (A+, A-, B+, B-, AB+, AB-, O+, O-)
   - location: { type: "Point", coordinates: [lng, lat] }
   - trustScore: Number
   - totalDonations: Number
   - isLiveTracking: Boolean
   - Indexes: `location: "2dsphere"`

3. BLOOD BANK MODEL (models/BloodBank.ts)
   - name: String (required)
   - address: String
   - contactPhone: String
   - owner: ObjectId -> User
   - location: { type: "Point", coordinates: [lng, lat] }
   - isVerified: Boolean
   - inventory: [{ bloodType: String, unitsAvailable: Number, lastRestocked: Date }]
   - Indexes: `location: "2dsphere"`, `"inventory.bloodType": 1`

6. REMAINING LIMITATIONS & PRODUCTION RECOMMENDATIONS
---------------------------------------------------------------------------
1. Seed Data: Currently queries simulated data generated by `seed.routes.ts`. In production, this should connect to local municipal registries or state-wide central blood bank feeds (e.g., eRaktKosh API).
2. Geocoding Service: Uses a fallback coordinate mapping dictionary for major cities. In production, a secure reverse-geocoding service (like OpenStreetMap Nominatim or Google Places API) should be activated.
3. Redis Persistence: The MockRedis implementation operates in-memory. For staging/production, a clustered Redis instance must be configured.
4. Healthcare Disclaimer: The medical notice is static and requires users to manually check availability by phone. Direct bank API ledger confirmations would streamline emergency dispatches.
